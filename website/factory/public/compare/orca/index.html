Oya Factory vs Orca

Both are free, MIT-licensed desktop apps that run coding agents in parallel, each task in its own git worktree. They differ in what they optimise for.

Oya FactoryOrca
LicenceMITMIT
PlatformsmacOS, WindowsmacOS, Windows, Linux
App shellTauri with the system webview; a Rust daemon per projectElectron
AgentsClaude Code, Codex, Antigravity, OpenCodeClaude Code, Codex and about 40 CLI agents
Your project's checks after every turnYes, with the verdict beside the replyNot described in its docs
Rewind a turnYes, a snapshot before every turnNot described in its docs
ApprovalsQuestions in the conversation, held by the daemonManual, Auto and Yolo permission modes
Stage one hunkYesYes, and single lines
Built-in editorNo — diffs to review, your editor to editYes, Monaco
Remote hosts over SSHNoYes
Phone appNoYes (beta)
Bots from Slack, Linear, GitHubNo; GitHub issues to tasks, and recurring tasksYes

Choose Oya Factory if

  • you want every turn proved: your checks run, a snapshot taken, the diff on screen, before you accept it;
  • you review in your own editor and want the app to stay out of the way;
  • you want a light native-webview app on macOS or Windows.

Choose Orca if

  • you run agents on a remote machine and steer them from a phone;
  • you want bots that take jobs from Slack or Linear;
  • you need Linux or one of the many other agent CLIs it supports.

Orca facts are from orca.dev and its documentation, read on 23 November 2026; they change often, so check the source.
