# Getting help with Keel

Keel is free and open source, and will always be free to use. Support is provided on a best-effort
basis, with no guaranteed response time. Claude subscriptions and other provider costs are separate.

## Find the right place

| You need | Where to go |
| --- | --- |
| Install Keel or connect Claude | [Getting started](README.md#get-started) |
| Understand a feature | [Feature guide](docs/features.md) and [README](README.md) |
| Build or contribute | [Contribution guide](CONTRIBUTING.md) |
| Report a bug, propose a feature, or ask a question | [Issue chooser](https://github.com/OyadotAI/keel/issues/new/choose) |
| Report a vulnerability privately | [Security policy](SECURITY.md) |
| Report harassment or a conduct concern | [Code of conduct](CODE_OF_CONDUCT.md) |

Use issues in `OyadotAI/keel` for source and app support. `OyadotAI/keel-releases` hosts downloads;
it is not the source repository or the place to send a code contribution.

## How to ask a useful question

1. Search existing issues and check the README's setup instructions.
2. Include your Keel version or source commit, macOS version, and what you were trying to do.
3. Include the smallest reproduction and exact redacted error. For session issues, say whether
   the session started in Keel, the CLI, VS Code, Orca, or another tool, and include its CLI version.
4. Say what you expected, what happened, and what you already tried.

Do not upload whole session transcripts, private repositories, access tokens, browser login links,
or screenshots containing customer data. A small synthetic example is better. Account billing and
subscription access questions belong with the provider; Keel cannot change those entitlements.

For a private security or conduct concern, email [mk@getoya.ai](mailto:mk@getoya.ai) using the
relevant policy above. Keep ordinary technical support in issues so others can benefit.
